### Цель
Перевести UI приложения на Vue 3, сохранив PHP как backend. Фронтенд должен быть модульным, масштабируемым и наследуемым, без монолитных компонентов.

### Контекст
Сейчас приложение рендерит UI на PHP (`app/index.php`) и использует сервисы:
- `app/Services/UserGreetingService.php` — получение данных пользователя и формирование приветствия.
- `app/Services/AccessControlService.php` — централизованная проверка доступа по контексту.

Нужно сохранить текущую backend-логику и вынести UI в Vue, обеспечив связку через JSON API.

### Бизнес-ценность
Гибкое развитие интерфейса, ускорение UI-итераций, переиспользуемые компоненты и единый UX для встроенных и внешних сценариев.

## Требования

### Функциональные
1. UI полностью отображается через Vue 3 (Composition API).
2. PHP остаётся backend-слоем (REST-интеграция Bitrix24, логирование, доступ).
3. Проверка доступа выполняется на backend, до загрузки основного UI.
4. Приветствие пользователя и контекст отображаются в Vue на основе backend JSON.
5. При ошибках API — нейтральные сообщения без падения приложения.
6. Встроенный контекст (Bitrix24) и прямой доступ учитываются одинаково, через backend.

### Нефункциональные
1. Нет больших монолитных компонентов — UI разбит на независимые компоненты.
2. Повторно используемая логика — через composables и сервисы.
3. Обработка ошибок и уведомления — через `BX.UI.Notification` (если доступен BX).
4. Данные экранируются и валидируются до вывода.
5. Логирование backend не нарушается, новые ошибки фронтенда логируются в консоль и/или отправляются на backend при необходимости.

## Детали и путь к результату
1. **Ошибка отсутствия ассетов Vue**  
   Причина: неверный путь к `public/` в `app/index.php`.  
   Исправление: вернуть корректную директорию и проверить сборку `public/vue/app.js` и `public/vue/app.css`.
2. **Невалидный JSON из `ui-state`**  
   Причина: возможный вывод из bootstrap (`settings.php`) ломал JSON.  
   Исправление: подавление вывода при bootstrap (`ob_start()`/`ob_get_clean()`).
3. **Всегда один пользователь (владелец токена приложения)**  
   Причина: отсутствие `AUTH_ID/DOMAIN` в запросах к API.  
   Исправление: получение auth через `BX24.getAuth()` и проброс в `/api/ui-state.php`.
4. **Потеря auth‑контекста между `/index.php` и `/api/ui-state.php`**  
   Причина: параметры приходили POST‑ом и не сохранялись.  
   Исправление: сохранение контекста в `$_SESSION` и использование в API.
5. **Неверное определение embedded/direct**  
   Причина: `AccessControlService` смотрел только `$_REQUEST`.  
   Исправление: учёт `$_SESSION` для `PLACEMENT/IFRAME/B24_FRAME`.
6. **BX24 API не инициализировался вовремя**  
   Причина: `BX24.getAuth()` вызывался раньше `BX24.init()`.  
   Исправление: подключение `api/v1` и `BX24.init()` перед монтированием Vue.
7. **Слипание текста в UI**  
   Причина: отсутствие визуального разделителя.  
   Исправление: добавлен разделитель `|` в `AccessContextInfo.vue`.
