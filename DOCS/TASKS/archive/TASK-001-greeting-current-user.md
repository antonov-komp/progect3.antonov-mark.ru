### Цель
Заменить вывод "Array (...)" на стартовой странице приложения на человекочитаемое приветствие с именем пользователя, который открыл приложение (не владелец приложения). Дополнительно вывести информацию: является ли пользователь администратором портала, где открыто приложение (внутри Bitrix24 или по прямой ссылке), а также отдел сотрудника.

### Контекст
Сейчас при старте приложения отображается "сырое" тело ответа REST API Bitrix24 с данными пользователя. Нужно вывести приветствие вида:  
`Привет, Марк Антонов!`  
Данные должны принадлежать именно текущему пользователю, открывшему приложение, а не владельцу приложения.

### Бизнес-ценность
Пользователь видит персонализированный интерфейс вместо технических данных, повышая доверие и удобство.

## Требования

### Функциональные
1. На стартовой странице выводится приветствие с именем и фамилией текущего пользователя.
2. Следующим предложением выводится: администратор ли пользователь, контекст открытия (внутри Bitrix24 или прямая ссылка) и отдел сотрудника.
2. Если фамилия отсутствует, показывать только имя.
3. При ошибке API вывести нейтральное сообщение, без остановки работы приложения.
4. В случае пустого имени — выводить "Привет!".
5. Факт открытия стартовой страницы фиксируется в локальном логе в корне приложения.
6. В лог пишутся: дата/время (UTC+3, Брест), ID пользователя, имя, фамилия, ID портала (если доступно), признак администратора, источник определения администратора, контекст открытия, отдел, результат запроса.

### Нефункциональные
1. Не выводить технические массивы/JSON в UI.
2. Обработка ошибок через логирование (AddMessage2Log или Bitrix\Main\Diag\Logger).
3. Валидировать и экранировать данные перед выводом (защита от XSS).
4. Соблюдать PSR-12 для PHP-кода.
5. Локальный лог хранить в каталоге `logs-apps` с ротацией по датам.
6. Лог не должен содержать секретов (токены, ключи, вебхуки).

## API-методы Bitrix24
- `user.current` — получить текущего пользователя  
  Документация: https://context7.com/bitrix24/rest/user.current  
- `user.get` — получить дополнительные поля пользователя (`UF_DEPARTMENT`, признаки администратора)  
  Документация: https://context7.com/bitrix24/rest/user.get  
- `user.admin` — проверить, является ли текущий пользователь администратором  
  Документация: https://context7.com/bitrix24/rest/user.admin  
- `department.get` — получить отдел пользователя  
  Документация: https://context7.com/bitrix24/rest/department.get  
- `profile` — альтернативно получить профиль текущего пользователя  
  Документация: https://context7.com/bitrix24/rest/profile

## Технические требования
- Ответ API не должен выводиться напрямую в UI.
- Формирование строки приветствия в PHP:
  - Использовать `htmlspecialchars()` для экранирования.
  - Обрабатывать `NAME` и `LAST_NAME` как опциональные.
- Дополнительно формировать следующее предложение:
  - `Администратор портала: да/нет/неизвестно; контекст: внутри Bitrix24/по прямой ссылке; отдел: <название или "не указан">.`
- Логировать ошибки запроса без прерывания выполнения.
- Локальный лог открытия страницы:
  - Файл: `/<project_root>/logs-apps/YYYY/MM/DD/app-open.log`.
  - Формат строки: `YYYY-MM-DD HH:MM (UTC+3, Brest) | user_id=... | name=... | last_name=... | portal_id=... | is_admin=yes|no|unknown | admin_source=user.current|user.get|user.admin|unknown | access=embedded|direct | department=... | status=ok|error | message=...`.
  - При ошибке API фиксировать `status=error` и краткий текст.
  - Использовать `file_put_contents(..., FILE_APPEND | LOCK_EX)` или встроенный Logger, направленный в файл.

## Пример кода (черновой)
```php
// Используется метод Bitrix24: user.current
// Документация: https://context7.com/bitrix24/rest/user.current

$userResult = $client->call('user.current');
$name = $userResult['result']['NAME'] ?? '';
$lastName = $userResult['result']['LAST_NAME'] ?? '';

$fullName = trim($name . ' ' . $lastName);
$safeName = htmlspecialchars($fullName, ENT_QUOTES, 'UTF-8');

$greeting = $safeName !== '' ? "Привет, {$safeName}!" : 'Привет!';
```
