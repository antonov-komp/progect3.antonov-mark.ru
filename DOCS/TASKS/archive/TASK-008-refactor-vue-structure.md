## Цель
Стандартизировать структуру Vue‑кода и точку входа приложения, обеспечить единый bootstrapping и безопасную загрузку контекста.

## Контекст
Vue‑фронтенд собирается Vite и отдаётся из `public/vue/`. Контекст приложения передаётся из `app/index.php` через `window.APP_REQUEST_CONTEXT`.

## Требования
### Функциональные
- Определить единый entry‑point приложения и структуру каталогов.
- Инициализировать приложение только после получения контекста.
- Отдельно выделить слой инициализации Bitrix24 SDK (`BX24`).

### Нефункциональные
- Vue 3 (Composition API).
- Логика разделена на модули и компоненты.
- Отсутствие прямых REST‑вызовов Bitrix24 с фронтенда.

## Модули/компоненты
- `frontend/` (исходники)
- `public/vue/app.js`, `public/vue/app.css` (сборка)
- Новый модуль: `frontend/src/bootstrap/` (предложение)

## Зависимости (иерархия)
1. `app/index.php` — выдаёт `APP_REQUEST_CONTEXT`.
2. `app/api/ui-state.php` — REST‑ендпоинт состояния.
3. Vite конфигурация (если есть).

## Этапы
1. Зафиксировать структуру `frontend/src/`:
   - `bootstrap/`, `services/`, `components/`, `views/`, `styles/`.
2. Реализовать entry‑point:
   - чтение `window.APP_REQUEST_CONTEXT`;
   - проверка наличия Bitrix24 SDK (`BX24`).
3. Добавить безопасную обработку ошибок и fallback‑сообщения.

## API‑методы
Не используются напрямую; только backend JSON.

## Технические требования
- Использовать `BX.ready()` для инициализации в embedded режиме.
- В случае отсутствия SDK — показывать понятное сообщение.

## Критерии приемки
- Vue инициализируется единообразно во всех сценариях.
- Контекст запроса валиден и не ломает приложение.
- Нет прямых REST‑вызовов Bitrix24 из фронтенда.

## Тестирование
- Загрузка без `APP_REQUEST_CONTEXT`.
- Загрузка с `APP_REQUEST_CONTEXT` и embedded режимом.
- Проверка graceful‑fallback, если `BX24` недоступен.
