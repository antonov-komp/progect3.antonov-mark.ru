## Цель
Стандартизировать загрузку и хранение `ui-state`, разграничить слой данных и UI, улучшить обработку ошибок.

## Контекст
Состояние интерфейса приходит от `app/api/ui-state.php`. Нужен единый слой данных, чтобы исключить разрозненные запросы и обработку ошибок.

## Требования
### Функциональные
- Создать сервис данных для `ui-state`.
- Реализовать единый store (Pinia или локальный store) для состояния.
- Добавить обработку статусов `ok/error` и сообщений.

### Нефункциональные
- Vue 3 Composition API.
- Явный контракт данных (ключи и значения).
- Ошибки backend отображаются безопасно, без XSS.

## Модули/компоненты
- `frontend/src/services/uiStateService.ts` (предложение)
- `frontend/src/stores/uiStateStore.ts` (предложение)
- Компоненты, отображающие greeting и доступ.

## Зависимости (иерархия)
1. `app/api/ui-state.php` — источник данных.
2. `frontend/src/bootstrap/` — инициализация.

## Этапы
1. Определить DTO `ui-state`:
   - `allowed`, `greeting`, `context_message`, `user`, `access`, `status`, `error_message`.
2. Реализовать сервис загрузки:
   - `fetch('/app/api/ui-state.php')`;
   - обработка сетевых ошибок и таймаутов.
3. Реализовать store:
   - состояния `loading/ready/error`.
4. Обновить компоненты на работу через store.

## API‑методы
Backend JSON:
- `GET /app/api/ui-state.php` — состояние UI.

## Технические требования
- Валидация типов данных (`string`, `boolean`, `null`).
- Без прямых REST‑вызовов Bitrix24.
- Сообщения об ошибках через `BX.UI.Notification` при наличии SDK.

## Критерии приемки
- `ui-state` загружается единожды и доступен всем компонентам.
- Ошибки отображаются корректно и безопасно.
- Нет дублирующихся запросов к `ui-state`.

## Тестирование
- Ошибка сети (симуляция недоступности эндпоинта).
- Ответ `status=error`.
- Ответ `allowed=false`.
