# TASK-036: Регистрация поля-встройки (кастомный тип с Handler) из интерфейса

**Дата создания:** 2026-02-11 (UTC+3, Брест)  
**Статус:** Завершена  
**Приоритет:** Средний  
**Исполнитель:** Bitrix24 Программист (Vue.js)

## Описание

Добавить возможность **регистрации поля-встройки** — пользовательского поля Bitrix24 CRM с **кастомным типом** (userfieldtype). В карточке CRM такое поле отображается как iframe с URL-handler’а. Контент handler’а (HTML/JS) загружает данные через REST API и показывает интерактивный интерфейс «внутри поля» (кнопки, выбор подписанта, запуск БП и т.п.).

**Целевая модель:** **модульная настройка из интерфейса** — пользователь создаёт поле нужного типа, а вся дальнейшая конфигурация (кнопки, зависимости и т.д.) выполняется в настройках уже созданного поля через единый модуль «Пользовательские поля».

Референс: [progect2.antonov-mark.ru](https://github.com/antonov-komp/progect2.antonov-mark.ru) — `register-userfield.php`, `contact-buttons.php`, `company-buttons.php`.

---

## Модульная архитектура полей-встроек

### Принцип

1. **Создание поля** — пользователь выбирает **тип встройки** (например, «С кнопками», «Зависимые поля») и создаёт поле в выбранном разделе.
2. **Настройка после создания** — в интерфейсе модуля «Пользовательские поля» у каждого созданного поля есть **«Настроить»**. Открывается форма настроек конкретного типа:
   - для «С кнопками» — настройка кнопок (текст, действие, источник данных);
   - для «Зависимые поля» — выбор полей-источников и правил отображения.
3. **Handler** получает конфигурацию через параметры (query, PLACEMENT_OPTIONS или отдельный API) и отображает UI согласно настройкам.

### Компоненты

| Компонент | Назначение |
|-----------|------------|
| **Каталог типов встроек** | Список предопределённых типов (С кнопками, Зависимые поля, …). Выбор при создании поля. |
| **Форма создания поля** | Выбор типа встройки → минимальные поля (название, код) → создание. |
| **Экран настроек поля** | Для каждого созданного поля — кнопка «Настроить» → форма с полями, специфичными для типа. |
| **Хранилище настроек** | JSON в SETTINGS поля CRM или отдельная таблица, доступная handler'у. |
| **Handler** | Единый (или по типу) handler, получает FIELD_NAME, ENTITY_VALUE_ID, настройки — рендерит UI. |

## Предопределённые типы полей-встроек (примеры)

### Тип 1: «С кнопками» (`buttons_view`)

**Описание:** Поле отображает набор кнопок. Действия кнопок настраиваются после создания поля.

**Создание поля:**
- Выбор типа «С кнопками»
- Название поля (например, «Поле с кнопками»)
- Код поля (опционально)
- Раздел (Сделки, Лиды, Контакты, Компании, **Смарт-процесс**)

**Настройки поля (после создания):**

| Параметр | Тип | Описание |
|----------|-----|----------|
| Кнопки | Массив | Список кнопок |
| ↳ Текст | string | Подпись кнопки |
| ↳ Действие | enum | Открыть URL, Запустить БП, Показать попап, Вызвать webhook и т.д. |
| ↳ Параметры действия | object | URL, ID БП, конфиг и т.д. |
| ↳ Стиль | enum | primary, secondary, danger и т.д. |
| ↳ Видимость | object | Условия отображения (роль, стадия и т.д.) |

**Пример конфигурации (JSON в SETTINGS):**
```json
{
  "buttons": [
    { "text": "Позвонить", "action": "open_url", "url": "tel:{{PHONE}}" },
    { "text": "Запустить БП", "action": "bizproc_start", "templateId": 123 }
  ]
}
```

---

### Тип 2: «Зависимые поля» (`dependent_fields_view`)

**Описание:** Поле показывает значения других полей сущности (или связанных сущностей) в компактном виде. Набор и способ отображения настраиваются.

**Создание поля:**
- Выбор типа «Зависимые поля»
- Название поля (например, «Контактные данные»)
- Код поля (опционально)
- Раздел (включая **Смарт-процесс**)

**Настройки поля (после создания):**

| Параметр | Тип | Описание |
|----------|-----|----------|
| Источник | enum | Текущая сущность / Связанный контакт / Связанная компания / Другое |
| Поля для вывода | Массив | Выбор полей (UF_*, стадии, контакт и т.д.) |
| ↳ Код поля | string | FIELD_NAME или системное поле |
| ↳ Подпись | string | Отображаемое название |
| ↳ Формат | enum | Текст, Ссылка, Телефон, Email, Да/Нет и т.д. |
| Макс. высота | number | px или auto |
| Сворачивание | bool | Показывать «Развернуть» при переполнении |

**Пример конфигурации:**
```json
{
  "source": "current_entity",
  "fields": [
    { "fieldName": "UF_CRM_PHONE", "label": "Телефон", "format": "phone" },
    { "fieldName": "UF_CRM_EMAIL", "label": "Email", "format": "email" }
  ],
  "maxHeight": 200,
  "collapsible": true
}
```

- Цель: единая точка входа — пользователь создаёт **поле-встройку** через модуль «Пользовательские поля», указывая URL handler’а и параметры.

## Сценарий использования (User Flow)

### Текущий (фаза 1)

- Пользователь открывает модуль «Пользовательские поля» → выбирает раздел (например, «Сделки»).
- В форме создания поля: переключатель **«Обычное поле»** / **«Поле-встройка (iframe)»**.
- В режиме «Поле-встройка» — ввод handler_url, user_type_id, название и т.д.

### Целевой (фазы 2–3, модульная настройка)

1. **Создание:** Выбор типа встройки из каталога («С кнопками», «Зависимые поля», «Свой handler») → название, код → создание.
2. **Настройка:** В таблице полей — кнопка «Настроить» у полей-встроек → форма настроек типа (кнопки, поля и т.д.).
3. **Отображение в карточке:** Handler получает настройки и рендерит UI.

---

### 1. Точка входа

- Пользователь открывает модуль «Пользовательские поля» → выбирает раздел (например, «Сделки»).
- В форме создания поля: переключатель **«Обычное поле»** / **«Поле-встройка (iframe)»**.

### 2. Режим «Обычное поле»

- Совпадает с TASK-035: название, код поля, тип (string, integer…), чекбоксы. Без изменений.

### 3. Режим «Поле-встройка» (фаза 1)

При выборе «Поле-встройка» форма дополняется:

- **URL handler’а** — обязательно (страница, которую Bitrix24 отобразит в iframe)
- **Код типа поля** (USER_TYPE_ID) — обязательно, уникальный (например, `my_buttons_view`). Валидация: `[a-z0-9_]`, макс. 50 символов
- **Название поля** (EDIT_FORM_LABEL)
- **Описание типа** (для userfieldtype)
- **Код поля** (FIELD_NAME) — опционально, авто-генерация
- **Раздел** — Сделки / Лиды / Контакты / Компании (смарт-процессы — по возможности)

### 4. Отправка и ответ

- Backend:
  1. Вызов `userfieldtype.add` (или `userfieldtype.update`, если тип уже есть)
  2. Вызов `crm.deal.userfield.add` (или lead/contact/company) с `USER_TYPE_ID` = код типа
- При успехе: закрыть форму, обновить список полей, уведомление «Поле-встройка создано».

## API-спецификация POST для mode=embed

**Request:**
```http
POST /api/user-fields.php
Content-Type: application/json

{
  "section": "deal",
  "mode": "embed",
  "handler_url": "https://example.com/handler.php",
  "user_type_id": "my_buttons_view",
  "label": "Мои кнопки",
  "field_name": "",
  "description": "Показывает кнопки действий"
}
```

**Response (success):** `{ "status": "ok", "field_id": 7010 }`

**Response (error):** `{ "status": "error", "error_message": "..." }`

**Валидация на backend:** handler_url — filter_var FILTER_VALIDATE_URL; user_type_id — preg_match `/^[a-z0-9_]{1,50}$/`; label — не пусто; section ∈ { deal, lead, contact, company } (смарт-процессы — фаза 4).

## Параметры handler'а (PLACEMENT_OPTIONS)

Bitrix24 передаёт в iframe URL handler'а с query-параметрами: `ENTITY_VALUE_ID` (ID сущности), `ENTITY_TYPE_ID` (1=лид, 2=сделка, 3=контакт, 4=компания), `ENTITY_ID` (CRM_DEAL и т.д.). Handler должен учитывать их для загрузки данных через REST API.

---

## Поддержка смарт-процессов

Поля-встройки (типы «С кнопками», «Зависимые поля» и произвольные) должны поддерживаться **в смарт-процессах** наравне с deal/lead/contact/company.

**Требования:**
- Метод `userfieldconfig.add` (или аналог) для смарт-процессов должен принимать кастомный `userTypeId`.
- Handler и хранилище настроек (SETTINGS) должны работать для `ENTITY_ID` вида `CRM_23`, `DYNAMIC_23` и т.д.
- В форме создания поля режим «Поле-встройка» доступен при выборе раздела «Смарт-процесс X».

**Проверка:** Создать поле-встройку в смарт-процессе → открыть карточку элемента → iframe отображается и получает PLACEMENT_OPTIONS.

## Ограничения

1. **Смарт-процессы:** В фазе 1 — только deal, lead, contact, company. В фазе 4 — добавление смарт-процессов.
2. **Scope Bitrix24:** Приложение должно иметь права на userfieldtype (виджеты).

1. Открыть модуль → Сделки → «Создать поле»
2. Выбрать «Поле-встройка»
3. Заполнить: URL `https://example.com/test.html`, код типа `test_embed_view`, название «Тест встройки»
4. Создать → проверить появление поля в таблице
5. Открыть карточку любой сделки в Bitrix24 → убедиться, что поле отображается как iframe
6. Повторить для Лидов, Контактов, Компаний
7. Проверить ошибку: неверный URL, дублирование кода типа
8. Проверить режим «Обычное поле» (регрессия TASK-035)
