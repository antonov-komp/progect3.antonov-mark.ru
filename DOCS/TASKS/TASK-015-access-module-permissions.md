## TASK-015: Модуль управления доступом (Vue, Bitrix24)

**Дата:** 2026-01-15 22:51 (UTC+3, Brest)  
**Статус:** Done  
**Приоритет:** High  
**Исполнитель:** Bitrix24 Vue.js Developer  

### Цель
Реализовать внутренний модуль управления доступом к приложению встраиваемого интерфейса Bitrix24, с выдачей прав по пользователям и отделам и сохранением настроек в локальный конфиг.

### Контекст
- Приложение запускается внутри Bitrix24 (embedded).
- Доступ регулируется локальным конфигом.
- Есть один супер‑админ, заданный в конфиге, он имеет полный доступ.
- Доступ выдаётся по пользователю и/или по отделу.
- При закрытом доступе показывается сообщение с ФИО супер‑админа.

### Требования
**Функциональные:**
- На стартовой странице вывести кнопку открытия внутреннего модуля доступа.
- Отображать супер‑админа по ID с ФИО.
- Список пользователей и отделов, множественный выбор.
- Сохранение в локальный конфиг с автосохранением (debounce).
- Отображение текущего состояния доступа (кто уже имеет доступ).
- При закрытом доступе: сообщение “Супер Админ {Имя Фамилия} закрыл доступ в приложение”.

**Нефункциональные:**
- Обработка ошибок без падения UI.
- Логирование ошибок на backend.
- Валидация входных данных.
- PSR‑12 для PHP.

### API Bitrix24

  https://context7.com/bitrix24/rest/user.search  
  https://context7.com/bitrix24/rest/user.get
- `department.get` — список отделов

Файл: `app/config/app-access.php`
```php
<?php

return [
    'global_enabled' => true,
    'super_admin_id' => 1,
    'allowed_users' => [],
    'allowed_departments' => [],
];
```

### Зависимости (иерархия)
1. Backend API (чтение/запись конфига доступа).
2. Bitrix24 REST (пользователи, отделы).
3. Frontend Vue (UI управления и доступ).

### Этапы реализации
1. **Контракт доступа**
   - Структура конфига: `global_enabled`, `super_admin_id`, `allowed_users`, `allowed_departments`.
   - GET/POST API для чтения и обновления.
2. **Сервис доступа (frontend)**
   - Запросы к API.
   - Автосохранение с debounce.
3. **UI управления доступом**
   - Списки пользователей и отделов.
   - Блок “Супер‑админ”.
   - Блок “Текущие права”.
4. **Проверка доступа**
   - Глобальный вход.
   - Проверка по пользователю или отделу.
5. **Проверки качества**
   - Сценарии доступа/запрета.
   - Валидация сохранения.

### Технические требования
- Vue 3, Composition API.
- Уведомления через `BX.UI.Notification`.
- Валидация входных данных.
- Без хранения секретов в коде.

### Критерии приёмки
- Супер‑админ отображается корректно по ID с ФИО.
- Списки пользователей и отделов отображаются и выбираются множественно.
- Сохранение выполняется автоматически, результат отображается.
- Текущее состояние доступа отображается на экране.
- При отказе в доступе выводится сообщение с ФИО супер‑админа.

### Примеры запросов
**GET** `/api/access-config.php`
```json
{
  "status": "ok",
  "config": {
    "global_enabled": true,
    "super_admin_id": "1",
    "allowed_users": ["5", "9"],
    "allowed_departments": ["12"]
  }
}
```

**POST** `/api/access-config.php`
```json
{
  "global_enabled": true,
  "allowed_users": ["5", "9", "21"],
  "allowed_departments": ["12", "14"]
}
```

### Тестирование
- Войти супер‑админом: доступ разрешён, видна кнопка управления.
- Включить/выключить `global_enabled`: проверка доступа.
- Разрешить доступ пользователю: проверка входа.
- Разрешить доступ отделу: проверка входа.
- Проверить сообщение отказа с ФИО супер‑админа.
