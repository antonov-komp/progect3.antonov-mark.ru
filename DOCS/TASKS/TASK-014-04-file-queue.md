# TASK-014-04: Очередь обогащения (JSON файлы)

Дата: 2026-01-15 16:45 (UTC+3, Брест)
Статус: draft
Приоритет: high
Исполнитель: Backend PHP (Bitrix24 REST)

## Цель
Организовать файловую очередь обогащения событий после получения первого webhook-события.

## Контекст
Нужно асинхронно обогащать данные, не задерживая ответ Bitrix24. Redis не используется — очередь на файловой системе.

## Требования
### Функциональные
- Каталоги:
  - `queue/pending/` — новые задания;
  - `queue/processing/` — в обработке;
  - `queue/done/` — успешно обработанные;
  - `queue/failed/` — ошибки.
- Создавать файл задания при каждом событии.
- Обработчик очереди:
  - читает `pending/`;
  - переносит файл в `processing/` (как блокировка);
  - выполняет REST‑обогащение;
  - сохраняет `enriched.json`;
  - переносит в `done/` или `failed/`.
- Обрабатывать задания пакетно (например, до 50 файлов за один запуск).

### Нефункциональные
- Без Redis.
- Защита от параллельной обработки (через атомарный rename).
- Логи ошибок — `logs/errors/`.
- Восстановление застрявших файлов из `processing/` по таймауту.

## Формат файла задания
```json
{
  "eventType": "ONCRMDEALADD",
  "entityType": "deal",
  "entityId": "123",
  "rawPath": "/outgoing-webhook/logs/ONCRMDEALADD/raw.json",
  "createdAt": "2026-01-15T16:45:00+03:00",
  "attempt": 0,
  "priority": "normal"
}
```

## Именование файлов очереди
- `YYYYMMDD_HHMMSS_eventType_entityId.json`
- Пример: `20260115_164500_ONCRMDEALADD_123.json`

## Повторные попытки
- Рекомендуемый максимум: 3 попытки.
- При ошибке — инкремент `attempt` и перенос в `failed/` после 3 попыток.
- Причину ошибки сохранять в `failed/<file>.error.json`.

## Обработка застрявших файлов
- Если файл в `processing/` старше 15 минут — вернуть в `pending/` и увеличить `attempt`.
- После 3 попыток — `failed/`.

## Запуск обработчика
- Планируется через cron (например, раз в минуту).
- Важно: обработчик не должен зависеть от внешних очередей.
- Допускается ручной запуск для отладки.

## Критерии приёмки
- Задания создаются в `pending/`.
- Обработчик переносит задания по стадиям.
- `enriched.json` создаётся после успешной обработки.
- Застрявшие задания возвращаются в обработку по таймауту.

## Тестирование
- Создать тестовое задание и прогнать через обработчик.
- Проверить `done/` и `failed/` пути.
- Проверить поведение при падении обработчика (файл остаётся в `processing/`).
