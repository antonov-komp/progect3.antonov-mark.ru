# TASK-016: Конфиг доступа к модульным плиткам на стартовой

**Дата создания:** 2026-01-21 12:00 (UTC+3, Брест)
**Статус:** Новая (черновик)
**Приоритет:** Средний
**Исполнитель:** Bitrix24 Программист (Vue.js)

## Описание
Сделать отдельный конфиг доступа к модульным плиткам на стартовой странице приложения. После прохождения глобального доступа пользователь видит приветствие, а набор плиток модулей определяется наличием доступа к каждому модулю по ID пользователя. На старте должны быть 5 стандартных модулей (заготовки), а при клике по плитке пользователь попадает на базовую страницу модуля с кнопкой «Назад».

## Контекст
Сейчас есть глобальная проверка доступа к приложению (TASK-015). Требуется дополнительный уровень — доступ к конкретным модулям, которые отображаются плитками на стартовой странице. Доступ на уровне модулей определяется по принадлежности `userId` и/или `departmentId` в конфиге модуля. Супер‑админ имеет доступ ко всем модульным плиткам независимо от конфигурации.

## Модули и компоненты
**Frontend:**
- `frontend/src/views/AppView.vue` — вывод плиток модулей
- `frontend/src/components/AccessManager.vue` — точка входа в настройки доступа
- `frontend/src/components/AccessModuleTiles.vue` — новый компонент плиток
- `frontend/src/components/AccessModulesManager.vue` — новый UI управления доступом к модулям
- `frontend/src/views/ModuleStubView.vue` — новая базовая страница модуля (заглушка)
- `frontend/src/router/index.js` (или существующий роутер) — маршруты модулей
- `frontend/src/services/accessConfigService.js` — расширение API-клиента
- `frontend/src/stores/uiStateStore.js` — хранение конфигурации и прав
- `frontend/src/styles/app.css` — стили плиток и формы

**Backend (зависимость, отдельная задача):**
- `app/api/access-modules.php` — чтение/запись конфига модулей
- `app/Services/AccessModulesService.php` — валидация и хранение конфига
- `app/config/app-modules-access.php` — локальный конфиг доступа

## Зависимости
- TASK-015: Глобальный доступ в приложение должен работать корректно.
- Backend API для доступа к модульному конфигу должен быть готов (GET/POST).

## Ступенчатые подзадачи
1. Спроектировать структуру модульного конфига (ключи модулей, заголовки, подзаголовки, иконки, доступ по `userId` и `departmentId`).
2. Добавить в `accessConfigService.js` методы для чтения/записи модульного конфига.
3. Реализовать `AccessModuleTiles.vue`:
   - рендер плиток модулей,
   - квадратный стиль, иконка, заголовок и подзаголовок,
   - фильтрация по `currentUserId` и `currentDepartmentId`,
   - супер‑админ видит все плитки.
4. Реализовать `AccessModulesManager.vue`:
   - список модулей,
   - выбор пользователей и отделов (ID/список) для каждого модуля,
   - автосохранение (debounce).
5. Добавить базовую страницу модуля `ModuleStubView.vue` и кнопку «Назад».
6. Настроить маршруты и переход по клику на плитку.
7. Интегрировать управление модулями в UI (кнопка/раздел в `AccessManager.vue`).
8. Добавить состояния загрузки/ошибок и уведомления через `BX.UI.Notification`.
9. Обновить стор `uiStateStore.js` для хранения модульных прав.

## API-методы (если применимо)

## Критерии приёмки
- Пользователь с глобальным доступом видит только плитки доступных модулей.
- При отсутствии доступа к модулю плитка не отображается.
- Плитка содержит иконку, заголовок и подзаголовок, квадратный стиль.
- По клику открывается базовая страница модуля с кнопкой «Назад».
- Доступ к модулю возможен по `userId` и/или `departmentId`.
- Супер‑админ видит все плитки независимо от конфига.
- Конфиг модулей сохраняется и загружается без ошибок.
- UI устойчив к ошибкам API (отображается сообщение и fallback).
- Управление правами на модули доступно супер‑админу (как в TASK-015).

## Тестирование
1. Войти пользователем с глобальным доступом и модульными правами — видны нужные плитки.
2. Убрать пользователя из `allowed_users` — плитка исчезает.
3. Убрать отдел из `allowed_departments` — плитка исчезает.
4. Выключить модуль `enabled=false` — плитка скрыта для всех.
5. Перейти в модуль по плитке — открылась базовая страница, работает кнопка «Назад».
6. Проверить доступ супер‑админа ко всем плиткам.
7. Проверить загрузку/сохранение конфига при ошибках API.
