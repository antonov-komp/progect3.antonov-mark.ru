# TASK-014: Исходящий вебхук Bitrix24 — эндпоинт, анализ событий, логирование

Дата: 2026-01-15 16:45 (UTC+3, Брест)
Статус: draft
Приоритет: high
Исполнитель: Backend PHP (Bitrix24 REST)

## Цель
Организовать новый раздел в корне приложения для приёма исходящих событий Bitrix24, с валидацией токена, анализом доступных событий и раздельным логированием по типам событий.

## Контекст
Нужно получить и фиксировать исходящие события Bitrix24 через отдельный эндпоинт, а также иметь скрипт для проверки, какие события разрешены для заданного токена. Логи должны группироваться по типам событий в отдельных папках. Данные приходят «сырые» — требуется обогащение через токен приложения (REST запросы Bitrix24) для получения полной карточки сущностей и справочников.

## Требования
### Функциональные
- Создать новый раздел в корне приложения: `/outgoing-webhook/`.
- Реализовать эндпоинт приёма событий (POST), принимающий токен в теле запроса.
- Реализовать скрипт анализа доступных событий по токену (REST вызов).
- Логировать события в раздельные каталоги по типам событий.
- Сохранять сырые входные данные и нормализованный payload.
- Обогащать входные события данными из Bitrix24 по токену приложения (описано в разделе «Обогащение») через очередь.

### Нефункциональные
- PSR-12.
- Логирование ошибок через `AddMessage2Log`/`error_log`, без остановки при нефатальных ошибках.
- Валидация входных данных, защита от XSS/SQL-инъекций.
- Секреты не хранить в коде (токены — только в .env или безопасных переменных).
- Очередь обогащения реализуется на файловых JSON (без Redis).

## Границы работ
### Входит
- Новый раздел `/outgoing-webhook/` с точкой входа и служебными скриптами.
- Скрипт анализа разрешённых событий по токену.
- Регламент логирования по типам событий.

### Не входит
- Реализация бизнес-логики конкретных событий (обработка сущностей CRM).
- Автоматическая регистрация событий в Bitrix24 (если не запрошено отдельно).

## Модули/компоненты
- Новый раздел: `outgoing-webhook/`
  - `outgoing-webhook/index.php` — эндпоинт приёма событий
  - `outgoing-webhook/tools/allowed-events.php` — анализ доступных событий
  - `outgoing-webhook/logs/` — корневая директория логов

## Зависимости (иерархия)
1. `app/crest.php` — текущий REST-клиент (если используется)
2. `app/config/app-access.php` — конфигурация доступа (если требуется)
3. Внешняя система: Bitrix24 REST API (облачная версия)

## Вопросы/ответы
- Q: Какой домен/URL будет зарегистрирован в Bitrix24?  
  A: Указать при настройке исходящего вебхука (предоставит заказчик).
- Q: Какие типы событий приоритетны?  
  A: Сделки, лиды, контакты, компании, смарт‑процессы, задачи, проекты, пользователи.
- Q: Обогащение выполнять синхронно в обработчике или асинхронно (очередь/cron)?  
  A: Асинхронно через очередь после получения первого события.
