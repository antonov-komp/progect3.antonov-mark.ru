# TASK-014-01: Анализ контекста и подготовка структуры

Дата: 2026-01-15 16:45 (UTC+3, Брест)
Статус: draft
Приоритет: high
Исполнитель: Backend PHP (Bitrix24 REST)

## Цель
Зафиксировать контекст Bitrix24, спроектировать структуру раздела `/outgoing-webhook/` и формат хранения логов/очереди.

## Контекст
События Bitrix24 приходят «сырые». Для дальнейшей обработки нужны:
- отдельный раздел в корне приложения;
- единый формат логов (raw/enriched);
- файловая очередь задач обогащения (без Redis).

## Предпосылки и решения
- Bitrix24: облачный (REST).
- Токен авторизации передаётся в теле POST (`token`).
- Очередь реализуется на файловых JSON без внешних брокеров.

## Требования
### Функциональные
- Определить точный URL эндпоинта (домен + путь).
- Спроектировать дерево директорий для эндпоинта, логов и очереди.
- Описать формат JSON для raw/enriched и очереди.

### Нефункциональные
- PSR-12.
- Секреты не хранить в коде и логах.
- Использовать файловую структуру, совместимую с ротацией логов.
- Раздел должен быть изолирован от `app/` и не ломать текущие эндпоинты.

## Структура раздела (целевой вид)
```
/outgoing-webhook/
  index.php
  tools/
    allowed-events.php
  queue/
    pending/
    processing/
    done/
    failed/
  logs/
    errors/
    allowed-events/
    <eventType>/
      raw.json
      enriched.json
      event.log
```

## Формат логов
### raw.json
- Полный неизменённый payload от Bitrix24.
- Поле `token` маскируется при сохранении.

### enriched.json
- Объединение raw + расширенные данные из REST API.
- Обязательные поля: `eventType`, `entityType`, `entityId`, `enrichedAt`.
- Поле `source` с указанием REST-метода, из которого пришли данные.

### event.log (строки)
```
2026-01-15T16:45:00+03:00 | IP=1.2.3.4 | event=ONCRMDEALADD | entityId=123
```

## Формат очереди (JSON)
Пример содержимого файла в `queue/pending/`:
```json
{
  "eventType": "ONCRMDEALADD",
  "entityType": "deal",
  "entityId": "123",
  "rawPath": "/outgoing-webhook/logs/ONCRMDEALADD/raw.json",
  "createdAt": "2026-01-15T16:45:00+03:00",
  "attempt": 0,
  "priority": "normal",
  "source": "outgoing-webhook"
}
```

## Соглашения именования
- `eventType` в верхнем регистре (например, `ONCRMDEALADD`).
- Папка логов равна `eventType`.
- Файлы очереди: `YYYYMMDD_HHMMSS_eventType_entityId.json`.

## Политика хранения
- raw и enriched храним минимум 30 дней (если не согласовано иначе).
- `event.log` допускает ротацию по дням.

## Риски
- Большие payload могут перегружать файловую систему.
- Отсутствие ротации логов может привести к переполнению диска.

## Критерии приёмки
- Определён точный URL эндпоинта.
- Зафиксирована структура директорий `/outgoing-webhook/`.
- Утверждён формат raw/enriched и очереди.
- Зафиксированы соглашения именования и хранения.

## Тестирование
- Проверить, что дерево директорий согласовано с планом деплоя.
- Проверить, что формат JSON подходит для последующей обработки.
- Проверить, что token маскируется в raw.json.
