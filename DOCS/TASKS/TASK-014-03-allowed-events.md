# TASK-014-03: Скрипт анализа доступных событий по токену

Дата: 2026-01-15 16:45 (UTC+3, Брест)
Статус: draft
Приоритет: high
Исполнитель: Backend PHP (Bitrix24 REST)

## Цель
Сделать скрипт `outgoing-webhook/tools/allowed-events.php`, который показывает, какие методы доступны по токену приложения, с фокусом на события и CRM.

## Контекст
Нужно понимать, какие события реально доступны текущему токену, чтобы корректно регистрировать вебхуки и планировать обогащение.

## Требования
### Функциональные
- REST-вызов `methods` для получения списка доступных методов.
- Фильтрация по группам:
  - `event.*`
  - `crm.*`
  - `tasks.*`
  - `sonet_group.*`
  - `user.*`
- Вывод результата в JSON и сохранение в `logs/allowed-events/allowed-events.json`.
- Сохранять «сырые» методы в `logs/allowed-events/raw-methods.json`.

### Нефункциональные
- Обработка ошибок REST с логированием.
- Не сохранять секреты.
- Данные сортировать по алфавиту для удобства сравнения.

## API-методы Bitrix24
- `methods`  
  Документация: https://context7.com/bitrix24/rest/methods

## Формат отчёта (пример)
```json
{
  "generatedAt": "2026-01-15T16:45:00+03:00",
  "groups": {
    "event": ["event.bind", "event.get"],
    "crm": ["crm.deal.get", "crm.lead.get"],
    "tasks": ["tasks.task.get"],
    "sonet_group": ["sonet_group.get"],
    "user": ["user.get"]
  }
}
```

## Сценарии использования
- Проверка доступных методов перед регистрацией событий.
- Валидация, что токен имеет права на нужные сущности.
- Формирование списка доступных методов для команды разработки.

## Критерии приёмки
- Скрипт возвращает список методов.
- Сформирован файл `logs/allowed-events/allowed-events.json`.
- Ошибки REST логируются в `logs/errors/`.
- Сформирован файл `logs/allowed-events/raw-methods.json`.

## Тестирование
- Запуск скрипта с валидным токеном.
- Проверка наличия файла отчёта.
- Проверка сортировки списка методов.
