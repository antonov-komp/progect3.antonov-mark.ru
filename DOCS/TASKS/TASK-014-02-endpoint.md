# TASK-014-02: Эндпоинт приёма событий

Дата: 2026-01-15 16:45 (UTC+3, Брест)
Статус: draft
Приоритет: high
Исполнитель: Backend PHP (Bitrix24 REST)

## Цель
Реализовать эндпоинт `/outgoing-webhook/index.php` для приёма исходящих событий Bitrix24 и первичного логирования.

## Контекст
События приходят в «сыром» виде, с токеном в теле POST. Эндпоинт должен быть устойчивым и быстро отвечать, передавая дальнейшую обработку в файловую очередь.

## Требования
### Функциональные
- Принимать только POST.
- Валидировать `token` из тела запроса.
- Извлекать `event`, `eventName`, `data`, `auth`, `ts` (если есть).
- Нормализовать `eventType` (например, `ONCRMDEALADD`).
- Сохранять:
  - `raw.json` с полным payload;
  - `event.log` с краткой записью;
  - задание в `queue/pending/`.
- Маскировать token при записи в raw.

### Нефункциональные
- Обработка ошибок без падения (логировать в `logs/errors/`).
- Защита от пустых/битых payload.
- Секреты не писать в логи.
- Ограничить размер входного payload (например, до 2 MB).

## Контракт входных данных (минимум)
- `token`: `string` — токен исходящего вебхука.
- `event`: `string` — код события (например, `ONCRMDEALADD`).
- `data`: `array|object` — полезная нагрузка.

## Валидация и нормализация
- Если `event` отсутствует, использовать `eventName`, иначе `unknown`.
- `eventType` приводить к верхнему регистру и удалять пробелы.
- `data` и `auth` сохранять как есть, без преобразования.

## Ответы эндпоинта
- `200 OK` — событие принято, запись в логи и очередь.
- `403 Forbidden` — неверный token.
- `405 Method Not Allowed` — не POST.

## Логирование
- `logs/<eventType>/raw.json` — сырой payload.
- `logs/<eventType>/event.log` — строковая запись с временем, IP, eventType.
- `logs/errors/` — ошибки валидации/сохранения.

## Пример входного запроса (упрощённо)
```json
{
  "token": "****abcd1234",
  "event": "ONCRMDEALADD",
  "data": {
    "FIELDS": {
      "ID": "123"
    }
  }
}
```

## Пример записи в event.log
```
2026-01-15T16:45:00+03:00 | IP=1.2.3.4 | event=ONCRMDEALADD | entityId=123
```

## Псевдокод
```php
if ($_SERVER['REQUEST_METHOD'] !== 'POST') { /* 405 */ }

$token = $_POST['token'] ?? '';
if (!hash_equals($expectedToken, $token)) { /* 403 + log */ }

$eventType = $_POST['event'] ?? 'unknown';
saveRaw($eventType, $_POST);
enqueue($eventType, $_POST);
```

## Критерии приёмки
- Эндпоинт принимает событие и отвечает `200 OK`.
- При неверном токене — `403` и запись в `logs/errors/`.
- Создаются логи `raw.json` и `event.log`.
- Создаётся файл задания в `queue/pending/`.
- token в raw.json замаскирован.

## Тестирование
- Отправка тестового POST с валидным `token`.
- Отправка тестового POST с неверным `token`.
- Проверка записи raw/event/queue.
- Отправка payload > 2 MB и проверка корректной ошибки.
