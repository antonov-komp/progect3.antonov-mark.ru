## Ключевые решения (из вопросов/ответов)
- Основные сценарии: embedded + direct (равнозначны), direct — временный режим.
- Установка: локальная (local app).
- Scopes: `user` + `department`.
- Обработка ошибок Bitrix24: все ключевые категории (`expired_token`, `QUERY_LIMIT_EXCEEDED`, `NO_AUTH_FOUND`, и др.).
- При ошибке профиля: UI показывается с предупреждением.
- Супер-админ: только по `super_admin_id`.
- `deny_direct` не блокирует супер-админа.
- Источник контекста: приоритет SDK → request → session.
- Только облачный Bitrix24 (без D7 ORM).
- Логи: ротация по месяцам, маскирование части ПДн.
- Кеш справочника: 30–60 минут, список до 200.
- Конфиг: сохранение по кнопке/подтверждению.
- Версионирование `app-access.php` не требуется.
- Outgoing webhook: отдельный worker/демон, идемпотентность обязательна (зафиксировать как зависимость проекта).
- Проверки перед релизом: security + тесты + статический анализ.
