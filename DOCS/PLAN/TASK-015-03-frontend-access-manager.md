## Цель этапа
Привести UI управления доступом в соответствие с согласованными правилами.

## Задачи этапа
1. **Ручное сохранение**
   - Заменить автосохранение (debounce) на явную кнопку «Сохранить».
   - Показывать статус: «Сохранено / Ошибка».
2. **Поведение при ошибке профиля**
   - При `status=error` показывать UI с предупреждением.
3. **Контекст и источник**
   - Использовать приоритет SDK → request → session при формировании контекста.
4. **Список пользователей/отделов**
   - Отображать до 200 элементов (или отображать признак ограничения).
5. **Уведомления**
   - Единый стиль BX.UI.Notification, уровни success/error.

## Детализация UI-изменений
1. **Кнопка сохранения**
   - Кнопка активна при наличии изменений.
   - До сохранения показывать «Есть несохраненные изменения».
2. **Статусы и ошибки**
   - Ошибка сохранения: `BX.UI.Notification` уровня error.
   - Успех: `BX.UI.Notification` уровня success.
3. **Ограничение списка**
   - При `items.length >= 200` показывать подпись «Список ограничен 200».
4. **Предупреждение профиля**
   - Баннер/alert при `state.status=error`.

## Примечания
- Direct-доступ временный: показать бейдж/подсказку в UI.
- Контекст должен отражаться пользователю (embedded/direct).

- Контекст и уведомления соответствуют требованиям TASK-015.
