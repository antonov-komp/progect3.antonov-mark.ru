## Цель этапа
Провести проверки качества и закрепить требования к логированию/безопасности.

## Задачи этапа
1. **Тестирование**
   - Проверить сценарии доступа/запрета (super_admin, allowed_users, allowed_departments).
   - Проверить direct-доступ (временно поддерживается).
   - Проверить ошибку профиля и предупреждение в UI.
2. **Логи**
   - Проверить частичное маскирование ПДн (ID/имя).
   - Зафиксировать ротацию логов по месяцам.
3. **Безопасность**
   - Убедиться, что секреты хранятся только в окружении.
   - Проверить входные данные и обработку ошибок Bitrix24.
4. **Статический анализ**
   - Запуск линтера/статического анализа (если есть в проекте).

## Чек-лист тестов
- Доступ супер-админа при `deny_direct=true`.
- Доступ пользователя из `allowed_users`.
- Доступ пользователя из `allowed_departments`.
- Отказ при `global_enabled=false`.
- Прямой вход (direct) — временно разрешен, но фиксируется в UI.
- Ошибка профиля Bitrix24 — UI остается доступным с предупреждением.

## Логи и маскирование
- Пример маскировки: `user_id=12` → `user_id=**12`, `name=Иван` → `name=Ив**`.
- Проверить, что маскирование применяется ко всем каналам `app-open`.

## Безопасность
- Секреты: только `.env`/окружение, без записи в репозиторий.
- Валидация входных данных: ID только числовые, пустые значения игнорируются.

## Отчетность
