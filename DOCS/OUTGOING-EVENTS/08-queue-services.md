# Queue Services: сервисы очереди обработки событий

**Дата создания:** 2026-01-26 (UTC+3, Брест)  
**Версия:** 1.0

## Назначение

Документ описывает сервисы, отвечающие за управление очередью обработки событий: создание заданий, их обработка, управление состоянием и логирование шагов.

---

## QueueService

**Файл:** `outgoing-webhook/services/Queue/QueueService.php`

### Назначение

Управление файловой очередью: получение списка заданий, подсчёт заданий в разных состояниях.

### Структура очереди

Очередь организована в виде файлов JSON в четырёх директориях:

- `queue/pending/` — задания, ожидающие обработки
- `queue/processing/` — задания, находящиеся в обработке
- `queue/done/` — успешно обработанные задания
- `queue/failed/` — задания, завершившиеся с ошибкой

### Методы

#### `listPending(int $limit): array`

Получение списка заданий, ожидающих обработки.

**Параметры:**
- `$limit` — максимальное количество заданий

**Возвращает:** массив объектов `QueueJob`

**Алгоритм:**
1. Поиск всех JSON-файлов в `pending/`
2. Сортировка по имени файла (хронологическая)
3. Ограничение до `$limit` заданий
4. Создание объектов `QueueJob` для каждого файла

**Пример:**
```php
$jobs = $queue->listPending(50);
foreach ($jobs as $job) {
    // Обработка задания
}
```

#### `count(string $dir): int`

Подсчёт количества заданий в указанной директории.

**Параметры:**
- `$dir` — путь к директории

**Возвращает:** количество JSON-файлов

**Пример:**
```php
$pendingCount = $queue->count($queue->getPendingDir());
```

#### `getPendingDir(): string`

Получение пути к директории `pending/`.

**Возвращает:** путь к директории

#### `getProcessingDir(): string`

Получение пути к директории `processing/`.

**Возвращает:** путь к директории

#### `getDoneDir(): string`

Получение пути к директории `done/`.

**Возвращает:** путь к директории

#### `getFailedDir(): string`

Получение пути к директории `failed/`.

**Возвращает:** путь к директории

## QueueJob

**Файл:** `outgoing-webhook/services/Queue/QueueJob.php`

### Назначение

Представление задания очереди. Инкапсулирует путь к файлу, данные задания и валидность.

### Свойства

- `$path` — путь к файлу задания
- `$data` — данные задания (массив)
- `$valid` — флаг валидности задания

### Методы

#### `getPath(): string`

Получение пути к файлу задания.

**Возвращает:** путь к файлу

#### `getName(): string`

Получение имени файла задания (без пути).

**Возвращает:** имя файла (например, `20260126_120000_ONTASKADD_123.json`)

#### `getData(): array`

Получение данных задания.

**Возвращает:** массив данных задания

**Формат данных:**
```json
{
  "requestId": "abc123...",
  "eventType": "ONTASKADD",
  "entityType": "task",
  "entityId": "123",
  "rawPath": "/path/to/raw.json",
  "createdAt": "2026-01-26T12:00:00+03:00",
  "attempt": 0,
  "priority": "normal",
  "source": "outgoing-webhook"
}
```

#### `setData(array $data): void`

Установка данных задания.

**Параметры:**
- `$data` — данные задания

**Использование:** для обновления данных (например, увеличение счётчика попыток)

#### `isValid(): bool`

Проверка валидности задания.

**Возвращает:** `true` если задание валидно, `false` если нет

**Валидность определяется:**
- При создании `QueueJob` проверяется, что данные — это массив
- Если данные не массив — задание помечается как невалидное

## JobStateService

**Файл:** `outgoing-webhook/services/Queue/JobStateService.php`

### Назначение

Управление состоянием заданий: переход между состояниями (pending → processing → done/failed), обработка повторных попыток, восстановление зависших заданий.

### Зависимости

- `QueueService` — для получения путей к директориям
- `ErrorService` — для логирования ошибок

### Константы

- `OUTGOING_WEBHOOK_MAX_ATTEMPTS` — максимальное количество попыток (по умолчанию: `3`)
- `OUTGOING_WEBHOOK_PROCESSING_TIMEOUT` — таймаут обработки в секундах (по умолчанию: `900` = 15 минут)

### Методы

#### `markProcessing(QueueJob $job): ?QueueJob`

Перевод задания в состояние "обработка".

**Параметры:**
- `$job` — задание из `pending/`

**Возвращает:** новое задание в `processing/` или `null` при ошибке

**Алгоритм:**
1. Перемещение файла из `pending/` в `processing/`
2. Чтение данных из файла
3. Создание нового объекта `QueueJob` с обновлённым путём

**Пример:**
```php
$processingJob = $jobState->markProcessing($pendingJob);
if ($processingJob === null) {
    // Ошибка перемещения
}
```

#### `markDone(QueueJob $job): void`

Перевод задания в состояние "завершено".

**Параметры:**
- `$job` — задание из `processing/`

**Алгоритм:**
1. Сохранение данных задания в файл
2. Перемещение файла из `processing/` в `done/`

**Пример:**
```php
$jobState->markDone($processingJob);
```

#### `markFailed(QueueJob $job, string $reason, ?string $method = null): void`

Перевод задания в состояние "ошибка".

**Параметры:**
- `$job` — задание из `processing/`
- `$reason` — причина ошибки
- `$method` — метод REST API (опционально)

**Алгоритм:**
1. Сохранение данных задания в `failed/`
2. Создание файла `.error.json` с информацией об ошибке

**Формат `.error.json`:**
```json
{
  "failedAt": "2026-01-26T12:00:00+03:00",
  "reason": "rest_error",
  "attempt": 3,
  "lastMethod": "crm.deal.get"
}
```

**Пример:**
```php
$jobState->markFailed($processingJob, 'rest_error', 'crm.deal.get');
```

#### `recoverProcessing(): void`

Восстановление зависших заданий.

**Алгоритм:**
1. Поиск всех файлов в `processing/`
2. Для каждого файла проверка возраста (время модификации)
3. Если возраст > `processingTimeout`:
   - Увеличение счётчика попыток
   - Если попытки исчерпаны — перемещение в `failed/`
   - Иначе — перемещение обратно в `pending/`

**Использование:** вызывается в начале каждого запуска обработчика очереди

**Пример:**
```php
$jobState->recoverProcessing();
```

#### `getMaxAttempts(): int`

Получение максимального количества попыток.

**Возвращает:** максимальное количество попыток

## QueueRunner

**Файл:** `outgoing-webhook/services/Queue/QueueRunner.php`

### Назначение

Оркестрация обработки очереди: получение заданий, их обогащение, обработка задач/комментариев, управление состоянием.

### Зависимости

- `QueueService` — управление очередью
- `JobStateService` — управление состоянием
- `EnrichmentService` — обогащение данных
- `ErrorService` — логирование ошибок
- `QueueStepLogger` — логирование шагов
- `TaskDetailsService` — детали задач
- `CommentDetailsService` — детали комментариев

### Методы

#### `run(int $limit): array`

Обработка очереди заданий.

**Параметры:**
- `$limit` — максимальное количество заданий для обработки

**Возвращает:** массив с результатами обработки

**Формат результата:**
```json
{
  "processed": 10,
  "processingMs": 5000,
  "queue": {
    "pending": 5,
    "processing": 0,
    "done": 100,
    "failed": 2
  }
}
```

**Алгоритм обработки:**

1. **Восстановление зависших заданий:**
   ```php
   $this->jobState->recoverProcessing();
   ```

2. **Обработка каждого задания из `pending/`:**
   - Перевод в состояние `processing`
   - Проверка валидности
   - Увеличение счётчика попыток
   - Извлечение данных из `raw.json` или `payload`
   - Определение `entityId` и `entityType`

3. **Логирование начала обработки:**
   ```php
   $this->steps->started([...]);
   ```

4. **Обогащение данных:**
   ```php
   $enriched = $this->enrichment->buildEnriched(...);
   ```

5. **Обработка ошибок обогащения:**
   - Если ошибка и попытки исчерпаны — перемещение в `failed/`
   - Если ошибка и есть попытки — возврат в `pending/`

6. **Сохранение обогащённых данных:**
   ```php
   outgoingWebhookWriteJson($enrichedPath, $enriched);
   ```

7. **Обработка задач:**
   ```php
   $taskData = $this->taskDetails->writeDetails(...);
   ```

8. **Обработка комментариев (ONTASKCOMMENTADD):**
   - Проверка, не была ли выполнена синхронная обработка
   - Если не была — вызов `handleCommentAdd()`

9. **Отслеживание изменений полей:**
   ```php
   $this->enrichment->detectFieldChanges(...);
   ```

10. **Завершение обработки:**
    - Перевод в состояние `done`
    - Логирование завершения

**Особенности:**

- **Пропуск синхронно обработанных комментариев:**
  Если комментарий уже обработан синхронно (ActivityFirst), задание пропускается:
  ```php
  if ($this->taskDetails->isActivityFirstProcessed($requestId, $entityId)) {
      // Пропуск
  }
  ```

- **Обработка ошибок:**
  При ошибке обогащения задание либо возвращается в `pending/` (если есть попытки), либо перемещается в `failed/` (если попытки исчерпаны).

**Пример использования:**
```php
$result = $runner->run(50);
echo "Обработано: " . $result['processed'] . "\n";
echo "Время: " . $result['processingMs'] . " мс\n";
```

## QueueStepLogger

**Файл:** `outgoing-webhook/services/Logging/QueueStepLogger.php`

### Назначение

Логирование шагов обработки очереди для отладки и мониторинга.

### Методы

#### `started(array $context): void`

Логирование начала обработки задания.

**Параметры:**
- `$context` — контекст обработки

**Формат контекста:**
```php
[
    'requestId' => 'abc123...',
    'eventType' => 'ONTASKADD',
    'entityType' => 'task',
    'entityId' => '123',
    'attempt' => 1,
    'jobFile' => '20260126_120000_ONTASKADD_123.json'
]
```

**Формат записи:** line-based JSON в `logs/queue-steps.log`

#### `finished(array $context): void`

Логирование завершения обработки задания.

**Параметры:**
- `$context` — контекст обработки

**Формат контекста:**
```php
[
    'requestId' => 'abc123...',
    'eventType' => 'ONTASKADD',
    'entityType' => 'task',
    'entityId' => '123',
    'attempt' => 1,
    'jobFile' => '20260126_120000_ONTASKADD_123.json',
    'status' => 'done', // или 'failed', 'skipped'
    'error' => '...', // опционально
    'reason' => '...' // опционально
]
```

**Возможные статусы:**
- `'done'` — успешно обработано
- `'failed'` — ошибка обработки
- `'skipped'` — пропущено (например, уже обработано синхронно)

## Жизненный цикл задания

```
1. Создание (index.php)
   └─> queue/pending/20260126_120000_ONTASKADD_123.json

2. Обработка (QueueRunner)
   └─> queue/processing/20260126_120000_ONTASKADD_123.json

3. Результат:
   ├─> Успех: queue/done/20260126_120000_ONTASKADD_123.json
   └─> Ошибка: queue/failed/20260126_120000_ONTASKADD_123.json
       └─> + .error.json с деталями ошибки
```

## Обработка ошибок

### Повторные попытки

- Максимальное количество попыток: `OUTGOING_WEBHOOK_MAX_ATTEMPTS` (по умолчанию: `3`)
- При ошибке обогащения задание возвращается в `pending/` с увеличенным счётчиком попыток
- Если попытки исчерпаны — задание перемещается в `failed/`

### Восстановление зависших заданий

- Таймаут обработки: `OUTGOING_WEBHOOK_PROCESSING_TIMEOUT` (по умолчанию: `900` секунд = 15 минут)
- При каждом запуске обработчика вызывается `recoverProcessing()`
- Задания, зависшие в `processing/` более таймаута, возвращаются в `pending/` или перемещаются в `failed/`
